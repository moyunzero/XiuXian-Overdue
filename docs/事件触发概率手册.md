# 修仙模拟器：事件触发概率深度手册

> 本手册为高级开发者与策划提供，深入解析 RNG 稳定性、权重计算算法以及事件门控的伪代码实现。

---

## 1. 确定性随机数 (Deterministic RNG)

为了防止玩家通过简单的「刷档」来规避负面事件，系统采用了 **Mulberry32** 伪随机数算法。

### 1.1 种子构造逻辑
```typescript
const getRNG = (state: GameState) => {
  // 结合 基础种子 + 天数 + 时段 + 存档槽位
  const derivedSeed = state.seed + state.school.day * 31 + state.school.slot * 997;
  return mulberry32(derivedSeed);
}
```
**结果**: 只要种子、天数和时段相同，生成的随机数序列是完全确定的。这意味着同一时间执行相同操作，触发的事件也将完全一致。

## 2. 事件抽检伪代码 (Trigger Logic)

系统在每次行动后执行以下逻辑：

```typescript
function actAfterAction(state) {
  const rand = getRNG(state);
  
  // 1. 优先级最高：身体偿还
  if (shouldTriggerRepayment(state, rand())) {
    return emitRepaymentEvent();
  }
  
  // 2. 叙事结局 (每局仅一次)
  if (shouldTriggerNarrative(state)) {
    return emitNarrativeEvent();
  }
  
  // 3. 精神崩溃 (PSY 门控)
  if (shouldTriggerCollapse(state, rand())) {
    return emitCollapseEvent();
  }
  
  // 4. 普通随机池 (加权随机)
  const baseP = 0.04 + state.econ.delinquency * 0.04;
  if (rand() < baseP) {
    const pool = filterEligibleEvents(state); // 检查 trigger, cooldown, family
    if (pool.length > 0) {
      return emitWeightedRandomEvent(pool, rand());
    }
  }
}
```

## 3. 加权随机算法 (Weighted Random)

在普通随机池中，事件通过 `weight` 字段进行竞争：

1.  **收集候选者**: 遍历 `events.json`，检查 `trigger` 条件、`cooldownDays` 以及 `family` 互斥。
2.  **计算总权重**: `TotalWeight = Sum(Event.weight)`。
3.  **抽取随机值**: `target = rand() * TotalWeight`。
4.  **遍历命中**:
    ```typescript
    let cumulative = 0;
    for (const event of pool) {
      cumulative += event.weight;
      if (target <= cumulative) return event;
    }
    ```

## 4. 互斥与冷却矩阵 (Cooldown Matrix)

| 冷却类型 | 持续时间 | 影响范围 |
| :--- | :--- | :--- |
| **ID 冷却** | `Math.max(3, event.cooldownDays)` | 仅限该特定事件 ID |
| **Family 冷却** | **3 天** | 整个族群（如所有「社交」类事件） |
| **身体偿还冷却** | **7 天** | 仅限身体偿还逻辑 |
| **精神崩溃冷却** | **10~15 天 (随机)** | 仅限精神崩溃逻辑 |

## 5. 极端情况下的概率修正

### 5.1 路线偏科 (Streak Boost)
当玩家连续执行同类行动（刷分或打工）超过 2 天时：
- **随机事件基础概率**：直接增加 **0.08** (8%)。
- **目的**: 增加刷分路线的不确定性，引入更多「系统性干扰」。

### 5.2 周结算日降权 (Weekly Downweight)
在周结算日（Day 7, 14, 21, 28）：
- **随机事件概率**：乘以 **0.65**。
- **目的**: 避免结算日志被大量的随机事件弹窗淹没，提升 UI 阅读体验。
