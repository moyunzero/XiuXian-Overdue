# 修仙模拟器：身体系统与部位偿还深度解析

> 本文档详细记录了游戏中「身体作为资产」的计算模型、偿还层级以及由此产生的长期生存影响。

---

## 1. 部位属性与估值矩阵 (Part Valuation)

每个部位在系统内都有其「基础价值」，并随修为实时浮动。

| 部位 ID | 基础价值 (Base) | 依赖关系 (Prereq) | 对应 3D 节点 (Mesh) |
| :--- | :--- | :--- | :--- |
| **LeftPalm** | ¥8,000 | 无 | `Hand_L` |
| **RightPalm** | ¥8,000 | 无 | `Hand_R` |
| **LeftArm** | ¥15,000 | `LeftPalm` | `Arm_L` |
| **RightArm** | ¥15,000 | `RightPalm` | `Arm_R` |
| **LeftLeg** | ¥18,000 | 无 | `Leg_L` |
| **RightLeg** | ¥18,000 | 无 | `Leg_R` |

### 1.1 动态估值公式 (The Asset Formula)
`Value = Base * (1 + faLi*0.1 + rouTi*0.2) * (1 - fatiguePenalty) * (1 - debasementPenalty)`
- **修为溢价**: 每提升 1 点法力增加 10% 估值，每提升 1 点肉体增加 20%。
- **疲劳减损**: `fatigue > 70` 时，每点疲劳扣除 1% 估值。
- **保底机制**: 最终价值不低于 `Base * 0.2`。

---

## 2. 偿还层级与依赖规则

系统通过 `BODY_PART_PREREQS` 强制执行偿还顺序：
- **逻辑**: 你不能在保留手掌的情况下偿还整只手臂。
- **显示**: 在 `RepaymentEvent` 弹窗中，未满足前提的部位会显示为灰色或带有「需先偿还 XX」的提示。

---

## 3. 偿还后的系统性后果 (Consequences)

### 3.1 属性修正 (Stat Penalties)
偿还特定部位会永久削弱相关行动：
- **手掌 (Palm)**: `study` (上课) 增益 × 0.95。
- **手臂 (Arm)**: `train` (炼体) 增益 × 0.90。
- **腿部 (Leg)**: `parttime` (打工) 收益 × 0.90。

### 3.2 疲劳与完整度 (Integrity)
- **累积惩罚**: `bodyIntegrity` 每偿还一次 × 0.8。
- **全局放大**: 所有行动的基础疲劳消耗乘以 `(2 - bodyIntegrity)`。
- **不可逆性**: 目前版本没有任何手段可以修复已偿还的部位。

### 3.3 社会评价：Marked (被标记)
只要偿还过任意部位，`bodyReputation` 永久变为 `marked`：
- **借贷**: 新借本金计入量上浮 1.2x。
- **补给**: 商店价格上浮 1.15x。

---

## 4. 叙事延迟反馈 (Narrative Echoes)

为了模拟「伤口愈合与心理适应」的过程，部位偿还不会立即产生感官日志：
1.  **T+0**: 弹窗执行偿还，数值即时改变。
2.  **T+3**: 在日结算时，系统检查 3 天前的记录，并向日志区推送一条「身体感受」日志。
    - *示例*: “今天握笔时，左手掌隐隐发麻，像是睡着了一样。”

---

## 5. 开发者调试
- **模拟偿还**: 在控制台或开发者工具中设置 `game.bodyPartRepayment.LeftPalm = true`。
- **触发弹窗**: 强制设置 `game.econ.lastPaymentDay = game.school.day - 28` 并执行一次 `act`。
