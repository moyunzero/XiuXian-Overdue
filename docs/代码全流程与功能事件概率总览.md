## 1. 数据架构 (Data Architecture)

### 1.1 顶层状态机：GameState
游戏状态以 `GameState` 接口为核心（[game.ts](file:///Users/moyun/code/xiuxian/xiuxian-sim/app/types/game.ts)），采用响应式引用（`ref`）管理。

```typescript
export interface GameState {
  started: boolean;      // 游戏进行状态
  seed: number;         // 全局随机种子
  stats: PlayerStats;   // 核心属性 (道心、法力、肉体、疲劳、专注)
  econ: EconomyState;   // 经济系统 (现金、各类债务、利率、逾期)
  school: SchoolState;  // 校园系统 (时间、分班、月考记录)
  contract: ContractState; // 契约系统 (进度、监工警觉)
  // ... 身体系统、PSY 系统、日志与历史记录
}
```

### 1.2 存储架构：Save V2
存档采用 **「容器化单键存储」**。
- **Key**: `kunxu_sim_save_v2`
- **Structure**:
  ```json
  {
    "saveSchemaVersion": 2,
    "activeSlot": "slot1",
    "slots": {
      "autosave": { "meta": { "day": 10, "tier": "普通班", "cash": 500 }, "state": { ...GameState } },
      "slot1": { ... },
      "slot2": { ... },
      "slot3": { ... }
    }
  }
  ```
- **写入机制**: 所有的持久化操作通过 `useGameStorage` 的 `commit` 函数执行，该函数具备 **500ms 防抖**，有效减少 `localStorage` 的 IO 压力。

## 2. 核心功能流转 (Functional Flow)

### 2.1 行动处理管线 (Action Pipeline)
位于 `useGame.ts` 的 `act(actionId)` 函数：

1.  **分流 (Branching)**:
    - 检查 `pendingEvent`：若有未处理事件，强制拦截所有输入。
    - 检查契约：若是 `rest` 行动且契约激活，先进行 `numbRestProbability`（麻木）判定。
2.  **前置计算 (Pre-calculation)**:
    - 调用 `mulberry32` 生成本时段确定性随机数。
    - 计算 `fatigueMult = 2 - bodyIntegrity`（身体受损对疲劳的放大系数）。
3.  **应用效果 (Apply Effects)**:
    - 属性变化：`stats.faLi`、`stats.rouTi` 等。
    - 经济变化：利息滚动、打工结算、补给扣费。
4.  **后置抽检 (Post-check)**:
    - 事件系统：按优先级调用 `Engine.shouldTriggerRepaymentEvent` 等函数。
    - 时间推移：`slot` 推进或调用 `endDay()`。

### 2.2 结算周期 (Settlement Cycle)
- **日结算 (`endDay`)**: 负责清理当日 `daySlotActions` 行动轨迹、衰减 `buyDebasement`、处理 3 天延迟的身体感受叙事。
- **周结算 (`WeekBoundary`)**: 
  - **月考评分**: 综合境界、负债、疲劳进行评分与分班映射。
  - **风控重估**: 根据逾期天数调整 `dailyRate` 和 `coreDebt`。
  - **计费系统**: 强制扣除学籍维护费与催收服务费。

## 3. 概率模型与逻辑门 (Probability & Gates)

### 3.1 随机事件门控
普通随机事件的触发概率 `baseP` 并非恒定，而是受逾期等级 (`delinquency`) 线性驱动：
- `baseP = 0.04 + (delinquency * 0.04)`。
- 在周结算日（Day 7, 14...），该概率会乘以 **0.65** 的降权系数，以腾出 UI 空间给结算日志。

### 3.2 身体偿还触发门
- **强制门 (Hard Gate)**: `daysSincePay >= 28`。
- **概率门 (Soft Gate)**: `delinquency >= 3` 且 `rand() < (0.25 + 0.20[逾期4] + 0.15[负债8w])`。

### 3.3 PSY 压力分数模型
精神崩溃的触发概率由 `psychPressureScore` 决定：
- **构成**: 契约缠绕 (60%) + 疲劳 (32%) + 专注损失 (14%) + 道心偏差 (1.8x)。
- **门控**: `gate = 0.18 + Score / 520` (上限 0.48)。

## 4. UI 组件通信逻辑

- **状态注入**: 通过 `useGameState()` 在各组件间共享同一个响应式 `game` 对象。
- **视觉反馈**:
  - `StatPanel.vue`: 实时计算并展示 `FullDebt` 与 `CreditLimit`。
  - `HumanModelViewer.vue`: 使用 `Three.js` 响应 `bodyPartRepayment` 的变化，实现模型部位的即时消散效果。
  - `LogPanel.vue`: 监听 `logs` 数组的变化，自动滚动至顶部的最新制度记录。
- **弹窗优先级**: `EventModal` 具有最高 `z-index` 且会 Teleport 到 `body`，确保叙事过程不被其他 UI 元素遮挡。
