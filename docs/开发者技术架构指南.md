## 1. 核心状态机与数据架构 (State & Storage)

### 1.1 响应式状态容器 (Reactive State)
项目采用 Nuxt 4 的 `useState` 机制，通过 `useGameState` 维护全局唯一的 `game` 对象。该对象是高度结构化的 POJO（Plain Old JavaScript Object），确保了状态的可预测性。

### 1.2 存档 V2 存储协议 (Save Container)
- **物理存储**: `localStorage.getItem('kunxu_sim_save_v2')`。
- **元数据 (Meta)**: 每个槽位包含 `day` (天数), `tier` (班级), `cash` (现金) 等快照，用于在 UI 列表页展示。
- **原子性保障**: 存档写入通过 `commit` 函数执行，包含 500ms 的防抖（Debounce）逻辑，防止高频 UI 交互（如快速连点行动）导致浏览器 IO 阻塞。

## 2. 核心行动数学模型 (Deep Dive: Action Math)

所有行动的最终增益遵循以下复合公式：
`FinalGain = Base * FocusMult * IntegrityMult * TierMult * ImbalanceMult * CollapseMult`

### 2.1 行动分项解析
| 行动 ID | 基础增益公式 | 身体部位修正 (Penalty) | 备注 |
| :--- | :--- | :--- | :--- |
| **study** | `(0.05 + FocusFactor * 0.06)` | 手掌伤残 (0.95x) | `FocusFactor` 包含班级加成。 |
| **tuna** | `(0.12 + (daoXin - 1) * 0.02)` | **无** | 吐纳无视身体损耗，是伤残后的保底手段。 |
| **train** | `(0.06 + (rouTi < 1.2 ? 0.02 : 0))` | 手臂伤残 (0.90x) | 疲劳 > 60 时触发 `(fatigue-60)/120` 概率的内伤。 |
| **parttime** | `(260~520 随机 + 120[示范班])` | 腿部伤残 (0.90x) | 收益受 `parttimePayImbalanceMultiplier` 压制。 |
| **buy** | 专注 +10, 疲劳 -6 | **价格上浮 (1.15x)** | `marked` 状态下价格由 260 升至 299。 |

### 2.2 疲劳与完整度联动
- **疲劳消耗**: `ActualFatigueUp = BaseFatigue * (2 - bodyIntegrity)`。
- **边际效应**: 当偿还 3 个部位后（完整度 ~0.51），玩家每动一次的疲劳代价接近初始的 **2 倍**。

## 3. 经济系统黑盒逻辑 (Economy Blackbox)

### 3.1 债务优先级 (Repayment Priority)
还款或身体偿还时的扣除顺序：
1.  **已累积利息 (debtInterestAccrued)**
2.  **系统费用 (collectionFee)**
3.  **债务本金 (debtPrincipal)**
*注意：核心债 (coreDebt) 仅能通过周结算重估减少。*

### 3.2 核心债演化算法 (Core Debt Evolution)
每周结算时根据信用表现调整：
- **信用破产 (逾期 ≥ 3级)**: `+300 + 100 * 逾期等级`。
- **信用优良 (0 逾期 & 7天内有还款)**: `-120` (不低于初始值的 50%)。
- **一般状态**: `+40` 或 `+100`。

## 4. PSY 与契约系统交互 (PSY-Contract Nexus)

### 4.1 契约反噬严苛度 (Strictness)
`strict = clamp(0.25 + vigilance / 160 + (totalDebt > 60000 ? 0.12 : 0), 0.15, 0.65)`
- **反噬后果**: 强制玩家在「被迫吐纳」或「被迫刷题」中选择，若选择「硬抗」，则 `vigilance +10` 且增加 120 罚金利息。

### 4.2 麻木休息逻辑 (Numb Rest)
- **触发概率**: `0.07 + (progress / 100) * 0.45` (最高 55%)。
- **后果**: 专注不回，疲劳正常扣减，`numbness +4`。
